# Ethics and consent

Language documentation should protect speakers as well as preserve language data.

## Minimum requirements

- Do not publish recordings or personal data without a clear publication/permission basis.
- Use anonymized speaker IDs by default when attribution is not already public or explicitly requested.
- Record whether a contributor wants public attribution when collecting new material.
- Avoid collecting unnecessary sensitive personal information.
- Make withdrawal and correction procedures clear for newly elicited material.

## Consent / publication status

Suggested workflow values for `consent_status`:

- `pending`
- `private-only`
- `public-text`
- `public-text-audio`
- `public-attributed`
- `source-published`

`source-published` means that the project's source already publicly identifies the speaker. It **does not** mean that this project has independently verified or obtained a new consent agreement from that speaker.

For ZB, the supplied published text identifies the narrator as Salihaw Rahimi. The repository records that published attribution in metadata but does not redistribute the supplied audio file.

These are project workflow labels, not legal advice. The maintainers should adapt them to the actual consent process used for future fieldwork and community contributions.
